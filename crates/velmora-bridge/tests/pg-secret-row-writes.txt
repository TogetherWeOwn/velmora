# Every catalogue statement, constraint, NOT NULL column and trigger that
# can raise an error on a table whose rows carry wrapped key material
# (buckets.bdk_wrapped, access_keys.secret_wrapped, extents.wrapped_file_key).
# Such an error's DETAIL can contain the row or key. This predates the
# single-Sync transport: binds never reach the log, the DETAIL of a failed
# CHECK, NOT NULL or UNIQUE can. A change here needs a review that the new
# entry cannot fail on a routine path (the caller validates first, or the
# failure is a bug).
# Format: kind, identity (statement: SHA-256 prefix, table, text head).
# Every CHECK and NOT NULL entry carries ` # <reason>`: why it cannot fail
# on a routine path. Validating these values in the client before the
# write is deferred (tracked outside this repository).
